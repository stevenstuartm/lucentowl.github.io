# Azure Study Guides Refinement Plan

Tracks the review-and-refine pass over all guides in `_guides/infrastructure/azure/`. Guides are consumed sequentially, in the order they appear in `assets/data/study_guides_config.json` (the "Azure" category) — that order already encodes the fundamentals-to-advanced learning path, so no guide should add its own prerequisite framing or cross-links to other Azure guides; the config ordering handles that.

**The checklist, the process rules, and the cross-domain gotchas live in [`.claude/content/guide-refinement-standard.md`](../.claude/content/guide-refinement-standard.md).** Read it first. This document carries only what is specific to the Azure pass: sources, domain gotchas, verified cross-guide facts, pre-flags, and the progress table.

## Sources

- Primary: [Microsoft Learn](https://learn.microsoft.com) and the official Azure product docs.
- Pricing: the Retail Prices API (see domain gotchas) — the `azure.microsoft.com` pricing pages are unreliable.
- Off-limits: marketing pages on `azure.microsoft.com` for any figure that will be asserted as fact. Several unverifiable claims in this pass trace to numbers that exist only there.

## Domain notes

**Item 7 (hierarchy and scope clarity)** in Azure means the management hierarchy — tenant → management group → subscription → resource group → resource — and the networking hierarchy — region → VNet → subnet → NIC. The canonical example of the gap: `azure-vnet-architecture.md`'s Application Security Groups section listed "All NICs in an ASG must be in the same VNet" as a constraint but never stated up front that ASGs are VNet-scoped, so a reader couldn't tell at a glance whether ASGs were a subscription-wide construct or something narrower.

**Item 9 (tag audit)** — measured across the 61 Azure guides before the pass: `azure` on 100%, `practical` on ~48, `infrastructure` on ~45, `cloud-computing` on ~35. So for this category: drop `azure` outright (redundant with the category), and treat `infrastructure` and `cloud-computing` as the filler tags to replace with real content signal. The specific nouns to reach for are services, patterns, and products — `aks`, `keda`, `gitops`, `service-mesh`, `workload-identity`, `cosmos-db`, `private-link` — not the vocabulary-table generics.

## Domain gotchas

- **`azure.microsoft.com` pricing pages time out; the Retail Prices API doesn't.** Rows 8, 10, and 11 all lost the pricing page to timeouts. `https://prices.azure.com/api/retail/prices?$filter=serviceName eq '<Service>' and armRegionName eq 'eastus' and type eq 'Consumption'` is public, unauthenticated, returns JSON, and is the same official rate data. Use it before flagging any pricing claim unverifiable. It has one failure mode: meters can be pre-registered for features that aren't shipped (row 11 found self-hosted-gateway meters on v2 tiers that three doc pages say don't exist), so it settles *prices*, not *feature availability* — cross-check the latter against docs.
- **Per-tier SLA percentages are not on MS Learn.** They live only in the SLA-for-Online-Services .docx, which WebFetch can't read, and the product docs deliberately say only "an SLA exists" and "zones or regions raise it." Don't assert 99.9x figures from memory; state has-SLA/no-SLA and link the SLA doc (row 11's pattern).
- **The archive-redirect tell in MS Learn's URL shape.** Learn moves an archived article under `learn.microsoft.com/previous-versions/azure/...` and stamps it `is_archived: true`; the live page then links back to it as "archived Classic API guidance." Watch also for `learn.microsoft.com/azure/<service-a>/<feature>` resolving to a canonical URL under `/azure/<service-b>/` — the feature moved services, usually to a different billing model and RBAC surface.
- **Azure docs are heavily zone-pivoted** between a legacy tier and the current one, and the two zones can describe architecturally different products. Confirm which pivot a claim came from. The FAQ often states a transition the concept pages don't.
- **Guides with heavy code still ahead:** rows 45-47 (pipelines, Actions), 48 (ML), 56-57 (serverless, Functions advanced), 59 (container patterns). Verify samples as claims.
- **Tier comparisons still ahead:** rows 43-44, 48-52. Confirm the tier *count* and the tier *names* before refining the table.
- **Remaining sibling links to remove** (`grep -rn 'href="/study-guides/\|](/study-guides/' _guides/infrastructure/azure/`): row 57 `azure-functions-advanced.md:14` and row 55 `azure-hybrid-cloud-architecture.md:225`. Row 55 line 375 links to `/study-guides/observability/observability-monitoring.html`, outside this pass's scope — it is still "where this fits" framing and should go.

## Cross-guide facts in force

Verified during earlier rows; applies to every remaining guide that touches the topic.

- **Front Door** Standard/Premium selects POPs by unicast via an internal Traffic Manager profile (changed Mar-Apr 2026). Anycast is classic-only.
- **gRPC through a layer-7 load balancer is Application Gateway for Containers, never Application Gateway.** App Gateway does not do HTTP/2 to backends.
- **APIM** gateway-to-backend HTTP/2 and pass-through gRPC are classic-only and in preview.
- **Azure Cache for Redis** is superseded by Azure Managed Redis. Any guide recommending a Redis tier needs the AMR migration path.
- **Service Bus** SBMP and the legacy SDKs (WindowsAzure.ServiceBus, Microsoft.Azure.ServiceBus, com.microsoft.azure.servicebus) retire **30 Sept 2026**.
- **Event Grid** dead-letters to a **blob container**, never a queue.
- **Durable Functions** docs moved to `learn.microsoft.com/azure/durable-task/` and are zone-pivoted between Durable Functions and the standalone Durable Task SDKs. Check which pivot a claim came from.
- **Azure CLI:** a JSON parameter file needs `--parameters @file.json`. The `@` marks it as a file. `.bicepparam` files take no `@`.
- **ARM complete mode** is documented as "will be gradually deprecated," with deployment stacks as the replacement.
- **Microsoft Sentinel** is unsupported in the Azure portal after **31 March 2027** and runs only in the Defender portal, where Defender XDR creates incidents and Microsoft-security and Fusion rule types are unavailable.
- **Log Analytics retention:** analytics retention 4-730 days plus total retention up to 12 years. The "1 day to 2 years" figure and the "archive tier" are both retired; long-term data comes back via search job.
- **Defender for Servers** no longer uses the Log Analytics agent or AMA except for the 500 MB ingestion benefit.
- **Azure Firewall has three SKUs** (Basic / Standard / Premium), not two. Basic caps at 250 Mbps, is threat-intelligence **alert-only**, and has no DNS proxy. Standard 30 Gbps, Premium 100 Gbps.
- **Azure Firewall rule order** is threat intelligence (highest priority, before any rule), then DNAT, then network, then application, then the built-in infrastructure rule collection, then default deny. Order is fixed by rule *type*, not by priority numbers. A network rule match terminates, so a broad `Allow 443 to Internet` network rule disables every application rule. Application rules never run on inbound connections and cover HTTP/HTTPS/MSSQL only, matching on Host header / SNI.
- **A Firewall Policy is shared,** attachable to many firewalls across regions and subscriptions. Free at zero or one association, billed at a fixed rate above that. Parent policy rule collection groups always outrank the child's; NAT rules are never inherited; threat-intel mode can only be overridden stricter.
- **Azure DDoS Protection is layer 3-4 only** and has three levels: free infrastructure protection, DDoS IP Protection ($199/IP/month US list), DDoS Network Protection (fixed plan fee covering 100 IPs). Break-even ~15 IPs. Rapid response (DRR), cost protection, and the App Gateway WAF discount are Network Protection only. Not supported on Virtual WAN, multi-tenant PaaS, or NAT Gateway public IPs. Thresholds are machine-learned and not user-configurable (custom policy is preview).
- **Virtual WAN secured hubs do not inspect spoke-to-spoke or inter-hub traffic** until **routing intent** is enabled. Firewall Manager manages Firewall Policy, DDoS plans, and WAF policies, never NSGs.
- **Key Vault access policies are NOT deprecated.** Both models stay fully supported. What has a date: from API version **2026-02-01** new vaults default to Azure RBAC, and **all control plane API versions before 2026-02-01 retire 27 Feb 2027** (needs Azure CLI 2.90.0+/Az PowerShell 16.3.0+). Any guide showing a Key Vault ARM/Bicep/Terraform resource needs its API version checked. The two models are exclusive: switching a vault to RBAC invalidates every access policy at once.
- **Every built-in Key Vault role is a DATA plane role**, including Key Vault Administrator ("cannot manage key vault resources"). `Key Vault Contributor` is the control-plane role and grants no data access. Vault firewall rules apply to the **data plane only**, so ARM/Bicep secret deployment through `management.azure.com` bypasses them.
- **Managed HSM is a separate resource type, not a vault tier**, and stores HSM keys only (no secrets, no certificates, no software keys). Vault tiers are Standard (FIPS 140-2 L1) and **Premium (FIPS 140-3 L3 on HSM Platform 2)**. Symmetric/AES (oct-HSM) keys are Managed HSM GA and Premium-vault **preview**, never Standard.
- **Azure Disk Encryption retires 15 Sept 2028**; ADE disks stop unlocking on reboot after that. Encryption at host is the replacement and the only option Defender for Cloud reports healthy. Any guide recommending ADE needs rewriting.
- **Key Vault soft delete cannot be disabled** once on; retention is 7-90 days (default 90), fixed **at vault creation**. Soft-deleting a vault also deletes its **RBAC role assignments and Event Grid subscriptions**, and recovery does not restore them. Key rotation **re-wraps DEKs, it does not re-encrypt data**. Secret `exp` is informational: a `get` on an expired secret still succeeds.
- **App Service/Functions cache Key Vault references and refetch every 24 hours.** Rotation is not picked up immediately without a config change, restart, or a POST to `config/configreferences/appsettings/refresh`.
- **Azure Blueprints retires 31 Jan 2027**, phased: 31 Jul 2026 no new definitions/versions, 31 Oct 2026 no definition edits and no new assignments, 31 Dec 2026 no assignment edits. Unexported definitions/versions/assignments are **permanently deleted** at retirement and blueprint **locks stop functioning**; deployed resources remain. Replacement is two features: **template specs (or Git)** for storage/versioning, **deployment stacks** for assignment, lifecycle, and deny-assignment locking.
- **Azure Policy has 11 effects** (addToNetworkGroup, append, audit, auditIfNotExists, deny, denyAction, deployIfNotExists, disabled, manual, modify, mutate) in a fixed evaluation order: disabled, append/modify, deny, audit, manual, auditIfNotExists, denyAction last; deployIfNotExists runs after the RP succeeds. Layering is **cumulative most restrictive** with no priority ranking. `denyAction` is the only effect that blocks deletion.
- **enforcementMode `DoNotEnforce`** is the correct dry run for a deny policy (audit is a different evaluation path). `Enroll` mode exists for staged opt-in. Assignments also carry `overrides`, `resourceSelectors`, `notScopes`, `nonComplianceMessages`, and `definitionVersion` pinning on built-ins.
- **Compliance % counts exempt + unknown + protected as compliant**, so exemptions inflate the score. Compliance states are Non-compliant, Compliant, Error, Conflicting, Exempt, Unknown, Protected, Not started, Not registered. Exemption categories are **Mitigated** (intent met another way) and **Waiver** (non-compliance accepted), not duration labels, and an exemption is **not deleted at expiry**.
- **deployIfNotExists/modify use two identities**: the caller's identity evaluates the existence condition, the assignment's managed identity performs the deployment. Existing resources need an explicit remediation task.
- **Defender for Cloud regulatory compliance beyond MCSB requires a paid Defender plan** (any except Servers P1 / API P1). Current standards are PCI DSS **v4.0.1**, ISO/IEC 27001:**2022**, NIST SP 800-53 **R5.1.1**, CIS Azure Foundations v2.1.0/v3.0 (v3.2.1-era names are stale). Non-auto-assessable controls are greyed out, not failed.
- **Management groups:** 10,000 per directory, **6 levels deep** (excluding root and subscriptions), one parent each. Root MG cannot be moved or deleted and needs Global Admin elevation. ARM caches the hierarchy up to **30 minutes**. A custom definition must be stored at or above its assignment scope.
- **Log Analytics retention is two settings:** analytics retention 4-730 days (default 30) and **total retention up to 12 years** (4,383 days), with long-term data reached via **search jobs**. **31 days are included in the ingestion price**, so cutting below 31 saves nothing. Table plans are **Analytics / Basic / Auxiliary**. `Usage`, `AzureActivity`, and all App Insights `App*` tables are free for 90 days. US East list: $2.30/GB ingestion, $0.10/GB/month retention.
- **Azure Monitor has four stores:** Azure Monitor Metrics (93 days, fixed, free), Log Analytics workspace (KQL), **Azure Monitor workspace** (a distinct resource type for managed Prometheus, PromQL, **18 months free**), and workspace-based Application Insights (physically inside Log Analytics). Container Insights = logs; Managed Prometheus = metrics.
- **Diagnostic settings never collect guest OS data.** Guest logs/perf require **AMA + a data collection rule**. DCR transformations filter before billing. The Log Analytics agent (MMA/OMS) is retired; Defender for Cloud uses only the Defender for Endpoint agent and Update Manager uses no agent.
- **Six alert types:** metric, log search, simple log search, activity log (**Resource Health and Service Health alerts are activity log alerts**), smart detection, Prometheus. **All activity log alerts are stateless.** Metric alerts resolve after 3 clear checks. **Metric alert rules are billed per monitored time series**, not free. Alert processing rules are the maintenance-window mechanism. Fired alerts are read-only, stored 30 days.
- **Application Insights instrumentation is OpenTelemetry.** The Azure Monitor OpenTelemetry Distro (`UseAzureMonitor()`) is the recommended path for ASP.NET Core, Java, Node.js, and Python; `Azure.Monitor.OpenTelemetry.Exporter` covers classic ASP.NET/console/WinForms; browsers stay on the Application Insights JavaScript SDK, which is not OpenTelemetry and never will be. The classic SDK 3.x releases are OpenTelemetry behind a `TelemetryClient` shim and are an interim step, not a destination. Any guide showing `TelemetryClient`, `TrackEvent`, `ITelemetryProcessor`, or `ITelemetryInitializer` as current practice is stale.
- **Instrumentation-key-only ingestion lost support 31 Mar 2025.** Connection strings (`APPLICATIONINSIGHTS_CONNECTION_STRING`) are required, and .NET SDK 3.x can fail at startup without one.
- **Classic (non-workspace) Application Insights resources retired 29 Feb 2024,** with automatic migration from May 2024. **Continuous export retired with them** and is incompatible with workspace-based resources; diagnostic settings (Storage / Event Hubs / partner) are the replacement. API keys survive migration but release annotations and the live metrics secure control channel need reconfiguring.
- **Availability tests: standard tests are the only current type.** Multi-step web tests retired 31 Aug 2024. URL ping tests retire **30 Sept 2026** and existing ones are deleted from resources. `TrackAvailability()` is archived classic API guidance. Standard tests are billed; ping tests were not.
- **Application Insights sampling is not adaptive sampling.** The Azure Monitor custom sampler decides at the end of span generation, hashes the trace ID, applies one rate to every telemetry type in a trace, and ignores upstream sampling decisions. Adaptive sampling is 2.x-SDK-and-Functions only (5 items/sec **per host**); .NET 3.x replaced it with `SamplingRatio` / `TracesPerSecond`; Java never had it. **Ingestion sampling now multiplies with SDK sampling** instead of standing down as it did under the classic SDKs.
- **Synapse SQL doc pages carry a Fabric successor notice** naming **Microsoft Fabric Data Warehouse** as the destination for new warehousing work, with an upgrade path and migration assistant for dedicated pools. Synapse is not retired and has no end date. Applies to every remaining guide that recommends Synapse.
- **Serverless SQL pool is read-only apart from CETAS.** No DML, no tables, no materialized views, no triggers; DDL is limited to views and security. It has no local storage, queries ADLS/Blob + **Cosmos DB analytical store + Dataverse** (never S3), reads Delta but **cannot write it or time travel**, has a **30-minute timeout that cannot be changed**, allows 100 databases and a 400 GB result set, and has **no result set caching**. Billing is *data processed* = storage reads + **uncompressed** intermediate transfer + CETAS writes, rounded up per MB with a **10 MB per-query minimum**, so `SELECT *` on a 1 TB Parquet table at 5:1 processes ~6 TB. Cost budgets (daily/weekly/monthly TB) reject the **next** query and never terminate the running one.
- **Dedicated SQL pool tables always have 60 distributions** (hash, round-robin, or replicated), fixed at creation; scaling changes nodes (~DWU/500), not distribution count. Concurrent queries cap at **128** and stop rising above DW6000c. Resource classes are static (`staticrc10`-`80`) and dynamic (`smallrc`/`mediumrc`/`largerc`/`xlargerc`, 3/10/22/70% at DW1000c+); Microsoft now points to **workload management** instead. **Materialized views are automatically and synchronously maintained** and used by the optimizer without being referenced. **Result set caching is dedicated-pool only, off by default**, 1 TB per database, and cache hits consume **no concurrency slots**.
- **Every current Azure Data Factory doc page carries the Fabric successor notice**, calling Data Factory in Microsoft Fabric "the next generation of Azure Data Factory" and directing new work there while offering existing estates an upgrade path. ADF is not retired and has no end date. Same framing obligation as row 21's Synapse-to-Fabric note.
- **ADF has exactly three integration runtimes and three trigger types.** Azure-SSIS IR is a **managed cluster of Azure VMs running the SSIS engine**, never Spark, and is unsupported in Synapse pipelines. Self-hosted IR is **Windows-only**, needs .NET Framework 4.7.2+ and a JRE, scales to **four nodes**, and makes outbound-only connections. IR precedence is self-hosted > managed-VNet Azure IR > global Azure IR, and either side of a Copy naming a self-hosted IR pulls the whole activity onto it. Triggers are schedule, tumbling window, and event-based (storage event + Event Grid custom event); **manual/on-demand execution is not a trigger type**. Only tumbling window supports backfill, retry, concurrency limits, and window variables, and only it waits for the pipeline run rather than reporting success at start.
- **ADF bills per *activity* run, not per pipeline run,** plus DIU-hours (copy on Azure IR) and vCore-hours (data flow execution **and debugging**). Data flow TTL is unavailable on the autoresolve IR. Per-pipeline billing is opt-in per factory and excluded from exported ARM templates.
- **Commitment discounts stack in a fixed order and only one of them is reversible.** Reservations apply **first** (more restrictive, up to 72% off), then the savings plan against its hourly commitment highest-discount-product-first (up to 65%, use-it-or-lose-it), then pay-as-you-go or the lower negotiated ACD rate. A **savings plan can never be cancelled or refunded**; a reservation is exchangeable for the same type and refundable up to **$50,000 in a rolling 12 months**. Reservations can be traded in for a savings plan, never the reverse. Utilization is computed over a best-fit **48-hour sliding window** and can transiently exceed 100%. There are now **two** savings plans: compute (1 or 3 year) and **databases (1 year only)**. Savings plans need EA, MCA, or MPA; other offer types get no discount.
- **No commitment discount covers licensing, storage, or networking.** A Reserved VM Instance covers VM compute only. Windows/SQL license cost comes off through **Azure Hybrid Benefit** (up to 80% Windows Server, up to 85% SQL Server), which needs core licenses with active Software Assurance **or qualifying subscription licenses**. AHB is centrally manageable at subscription/billing-account scope for **SQL Server only**; Windows Server stays resource-level. Reservation attributes are SKU, region **where applicable**, and scope, so VM reservations have **instance size flexibility but no region flexibility**.
- **Microsoft publishes commitment discounts as ceilings ("up to 72%"), never as per-service ranges.** Any table giving a per-service 1-year/3-year percentage band is fabricated precision.
- **Budgets never stop spending** ("resources aren't affected, and your consumption isn't stopped"), evaluate every 24 h on **actual (never amortized)** cost, and allow **5 thresholds and 5 email addresses** at 0.01-1000%. Budget **action groups work at subscription and resource group scope only**. **Cost anomaly detection is subscription-scope only**, free, 60-day forecast baseline, runs 36 h after the UTC day, max **5 anomaly alert rules per subscription**, unavailable in sovereign clouds.
- **The Cost Management connector for Power BI is in maintenance mode and no longer updated.** Microsoft moved Power BI guidance to **Exports**, which cover actual/amortized/**FOCUS**/price sheet/reservation details, recommendations, and transactions in CSV or Parquet. File partitioning is always on and cannot be disabled; read `manifest.json` rather than guessing file names.
- **Azure Automation lost two features to retirement on 31 Aug 2024,** both alongside the Log Analytics agent: **Update Management** (replaced by **Azure Update Manager**, a separate service with no Automation, Log Analytics, or AMA dependency, storing data in Azure Resource Graph and using per-resource RBAC) and the **agent-based Hybrid Runbook Worker** (agent-based jobs stopped **1 Apr 2025**; the extension-based V2 worker, installed through the VM extension framework with a system-assigned managed identity, is the only supported platform). **Azure Automation State Configuration retires 30 Sept 2027** and is replaced by **Azure machine configuration** delivered through Azure Policy; its Linux half retired 30 Sept 2023.
- **Azure sandbox limits:** three-hour **fair share** ceiling (not a shorter timeout), 400 MB memory, 1 GB temp disk, 1,000 sockets, max 10 jobs per sandbox, .NET Framework 4.7.2 only, and no executables, subprocesses, WMI, or elevation. Hybrid Runbook Workers are exempt from fair share entirely. Supported runbook runtimes are **PowerShell 7.6 / 7.4 / 5.1 and Python 3.10**; a webhook cannot start a Python runbook at all and misencodes input parameters for PowerShell 7.
- **Arc-enabled data services means SQL Managed Instance,** full stop. The PostgreSQL/Citus Hyperscale offering is no longer part of the product.
- **Logic Apps Consumption bills per action and, separately, per managed-connector call.** MS Learn gives no consistent connector count (400+ and 450+ appear on different pages), so don't assert one.
- **NSG flow logs retire 30 Sept 2027 and can no longer be created.** Traffic Analytics on them ends and the NSG flow log resources are deleted (Storage records remain). Replacement is **VNet flow logs**; D/E/F v6 VM families support only those.

- **Power BI Premium per-capacity P SKUs are retiring.** New P SKUs are no longer sold and each subscription ends at its agreement term; EA customers with an active agreement can renew existing capacity until the EA term ends. Replacement is Fabric **F SKUs** (P1 to F64, P2 to F128, P3 to F256, P4 to F512, P5 to F1024). Lapse means a 30-day grace period, throttling from day 31, and all operations rejected from day 91. **Pro, PPU, and the EM/A embedding SKUs are NOT part of this retirement.** Autoscale does not exist on F SKUs (on-demand resizing replaces it), and billing moves from M365 commitment to Azure. Any guide recommending "Power BI Premium capacity" needs rewriting.
- **F64 is the free-viewer threshold.** On F64 and larger, a free license plus the Viewer role can consume content. On F2-F32 every viewer still needs Pro or PPU. Headcount rules of thumb ("100+ users justifies capacity") are fabricated; this boundary is the real one.
- **Semantic model size is a licensing limit, not an engine limit:** shared capacity/Pro 1 GB (plus a 10 GB cap on uncompressed data processed during refresh, 8 scheduled refreshes/day), PPU 100 GB (48/day), Fabric F2-F8 3 GB, F16 5, F32 10, F64 25, F128 50, F256 100, F512 200, F1024+ 400. Refresh roughly doubles the footprint. A 225-second visual render timeout applies on every SKU.
- **Power BI real-time streaming is retiring.** Creation of push, streaming, and PubNub semantic models and streaming data tiles stays enabled until **31 Oct 2027**, then stops; existing models are unaffected. Replacement is Fabric Real-Time Intelligence. The three types differ: push writes to a real database (1 req/sec, 16 MB/req, 1M rows/hour) and supports full reports; streaming holds about an hour in a temporary cache with no database and only custom streaming tiles; PubNub stores nothing. Azure Stream Analytics output uses pushStreaming with a 200,000-row basicFIFO policy. Automatic page refresh is DirectQuery-only.
- **Gateway names changed.** The current set is **on-premises data gateway** (standard mode, multi-user, all supported services, clusterable), **on-premises data gateway (personal mode)** (single user, Power BI only), and **virtual network (VNet) data gateway** (Microsoft-managed, no install, connects to sources secured by an **Azure VNet, not on-premises**). "Personal Gateway" and "Enterprise Gateway" are stale labels. Limits: 1,000 data sources per cluster, 16 MB uncompressed DirectQuery response, roughly 5-hour credential cache, only the last six monthly releases supported.
- **Dataflow Gen1 is legacy** and "won't receive new feature investment"; Gen2 (Fabric Data Factory) is the recommended path for customers with Fabric capacity, writing Delta to Fabric destinations. Gen1 output is Common Data Model format in Power BI storage or a bring-your-own ADLS Gen2 account. Pro/PPU customers without Fabric stay on Gen1.
- **Endorsement has three badges, not two:** Promoted (any user with write permission), Certified (only users a Fabric admin designates; delegable per domain), and **Master data** (admin-designated users, data-bearing items only). Certification and master data must be enabled at the tenant. Every Fabric/Power BI item **except Power BI dashboards** can be promoted or certified.
- **A sensitivity label classifies; a Purview protection/publishing policy enforces.** A label does not by itself block export. Labels propagate downstream and survive supported export paths (Excel, PDF, PowerPoint, Analyze in Excel, .pbix download) but **not CSV/TXT export or cross-tenant access**. Blocking Excel export is a tenant setting.
- **Deployment pipelines take 2 to 10 stages (default 3: Development, Test, Production), work by item pairing, and have no rollback.** Git integration is the versioning mechanism. Deployment rules swap data sources and parameters per stage. From **12 Feb 2026** pipelines dropped support for semantic models not upgraded to Enhanced Metadata.
- **User-defined aggregations require the detail table to be in DirectQuery storage mode**, not Import. Aggregation tables are hidden and hit transparently; a Precedence value orders multiple aggregations. RLS must filter both the aggregation and the detail table (filtering only the aggregation is rejected outright). Automatic aggregations is a separate capacity feature.
- **The monitoring app is the Microsoft Fabric Capacity Metrics app** (supersedes the Premium metrics app). Pages: Health, Compute (14 days), Storage (30 days), Timepoint (30-second intervals). Data lands 10-15 min behind, it has **no alerting** (use Fabric capacity events), and it does not support PPU.
- **Paginated reports no longer require Premium.** Licensing matches Power BI reports: free license publishes to My Workspace, Pro/PPU elsewhere with at least Contributor. Authored in **Power BI Report Builder** (free download), no underlying data model, exports to Excel/Word/PowerPoint/PDF/accessible PDF/CSV/XML/MHTML, and cannot be pinned to dashboards.
- **Direct Lake** is a Fabric-capacity-only storage mode reading Delta tables in OneLake via VertiPaq; "refresh" is metadata **framing**. Two variants: Direct Lake on OneLake (multi-source, no fallback) and Direct Lake on SQL (single source via the SQL analytics endpoint, falls back to DirectQuery for non-materialized views and SQL RLS). **Direct Lake cannot use any gateway.** Power BI service semantic model modes remain Import, DirectQuery, and Composite; Import compresses roughly 10:1 and must load fully into memory.
- **Azure Analysis Services has no retirement date.** Tiers are Developer, Basic, Standard, sized by QPU and memory, with query replica scale-out up to 7 additional replicas. Microsoft supplies an automated migration to Power BI semantic models on F SKU, PPU, or Power BI Embedded. The old "non-Power BI clients need AAS" argument is weak because capacity/PPU semantic models expose an XMLA endpoint.
- **Cosmos DB does not need an intermediate export for Power BI.** The Azure Cosmos DB v2 connector supports Import and DirectQuery (with pushdown), and Fabric **mirroring** replicates Cosmos DB into OneLake in near real-time without consuming RUs, which Power BI then reads in Direct Lake mode.
- **QuickSight is now Amazon Quick Sight inside Amazon Quick Suite** (rebranded Oct 2025). Authoring is **browser-only, there is no desktop client** (any guide claiming a desktop tool, beta or otherwise, is fabricating). Roles are Reader, Author, Reader Pro, Author Pro, plus capacity-based reader sessions; 10 GB SPICE is included per provisioned Author. It has native joins, filters, type changes, and calculated fields, so "no data prep without Glue" overstates the gap.
